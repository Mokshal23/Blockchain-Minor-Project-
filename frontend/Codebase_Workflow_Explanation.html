2. Development Workflow (How We Built It Step-by-Step)

Phase 1: Python Engine & Custom SHA-256 Ledger

  • Built Flask API endpoints (/api/campaigns, /api/campaigns/:id/contribute, /api/blockchain).
  • Implemented custom Block class with hashlib.sha256 hashing chaining block index, timestamp, JSON payload, and previous block hash.
  • Configured Vercel serverless integration using /tmp/database.db because Vercel serverless filesystems are read-only.

Phase 2: Solidity Smart Contracts & EVM Engine

  • Implemented EquityCampaign.sol and LendingCampaign.sol inheriting OpenZeppelin ReentrancyGuard.
  • Auto-initialized Milestone 0 in contract constructors so campaigns are immediately ready for contributor voting upon deployment.
  • Implemented pull-based debt withdrawals (withdrawRepayment()) in LendingCampaign.sol to prevent reentrancy attacks.

Phase 3: Hardhat Optimization & Testing

  • Configured hardhat.config.js with Solidity optimizer (runs: 200) and allowUnlimitedContractSize: true.
  • Wrote automated unit tests in contracts/test/Crowdfunding.test.js (3/3 passing).

Phase 4: Unified Frontend Integration

  • Integrated Ethers.js v6 for Web3 provider interaction.
  • Built inline input fields (`[ 1.0 ] ETH` `[ Contribute Now ]`) directly on campaign cards.
  • Implemented auto MetaMask reconnection on page refresh and account change listeners.

3. Core Code Snippets & Implementation Analysis

3.1 Python SHA-256 Block Hashing Logic (`api/index.py`)

class Block: def __init__(self, index, timestamp, data, previous_hash): self.index = index self.timestamp = timestamp self.data = data self.previous_hash = previous_hash self.hash = self.calculate_hash() def calculate_hash(self): block_string = f"{self.index}{self.timestamp}{json.dumps(self.data)}{self.previous_hash}" return hashlib.sha256(block_string.encode()).hexdigest()

3.2 Solidity Milestone Voting & Auto-Release (`EquityCampaign.sol`)

function voteMilestone(uint256 _milestoneId, bool _approve) external { require(_milestoneId < milestones.length, "Invalid milestone ID"); require(contributions[msg.sender] > 0, "Only contributors can vote"); require(!hasVoted[_milestoneId][msg.sender], "Already voted"); Milestone storage m = milestones[_milestoneId]; require(!m.isExecuted, "Milestone already executed"); uint256 voteWeight = contributions[msg.sender]; hasVoted[_milestoneId][msg.sender] = true; if (_approve) { m.votesFor += voteWeight; } else { m.votesAgainst += voteWeight; } // Auto-release funds if YES votes exceed 50% majority threshold if (m.votesFor > (currentAmount / 2) && !m.isApproved) { m.isApproved = true; _executeMilestoneRelease(_milestoneId); } }

3.3 Solidity Pull Repayment Pattern (`LendingCampaign.sol`)

function withdrawRepayment() external nonReentrant { require(lenderPrincipal[msg.sender] > 0, "Not a lender"); uint256 principal = lenderPrincipal[msg.sender]; uint256 maxShareFromPool = (totalRepaidPool * principal) / currentAmount; uint256 alreadyWithdrawn = lenderWithdrawn[msg.sender]; require(maxShareFromPool > alreadyWithdrawn, "No new repayments available"); uint256 claimable = maxShareFromPool - alreadyWithdrawn; lenderWithdrawn[msg.sender] += claimable; // Update state first (bool success, ) = msg.sender.call{value: claimable}(""); // Transfer ETH require(success, "Withdrawal transfer failed"); }

4. End-to-End System Workflow Summary

Dual Engine Dispatching:
  1. When creating a campaign, the model type dictates the engine route (Donation/Reward $\rightarrow$ Python REST API; Equity/Lending $\rightarrow$ Solidity Factory Contract).
  2. On the frontend, app.js queries both the Python API and Ethereum EVM simultaneously and aggregates all campaign cards onto a unified grid.
  3. When a user interacts with a card, the frontend dispatches to the corresponding engine seamlessly!
